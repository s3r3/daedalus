# ADR-0007: Background Server Lifecycle, Startup Menu, and Tray Fallback

## Context

The user wants a bare `daedalus` invocation to feel like launching an app:
one background server, a menu (`1` CLI, `2` Web), and a tray/startup icon
whose Quit stops the server. The same command must also work in headless
shells where no desktop session exists, and existing commands (`daedalus
run`, `daedalus cancel <id>`, `--json` flows) must not regress.

## Decision

1. **One lifecycle module in the CLI.** `Daedalus/cli/src/launcher.ts`
   owns the PID/state file (`.daedalus/daemon.json`), an HTTP `/health`
   probe, log file discovery, and single-instance reuse.
   The state file records `pid`, `host`, `port`, `started_at`, and
   `server_url`; it is written atomically with mode `0o600`.
2. **Bare `daedalus` behavior**:
   - if a healthy server already answers `/health`, reuse it;
   - otherwise start exactly one background server child by spawning the
     server entrypoint and wait until healthy; `daedalus serve --daemon`
     is a convenience command that uses the same `ensureDaemon()` path;
   - print the menu `1` CLI, `2` Web, `0`/`q` leave, and wait for the user's
     choice; `2` opens the server URL in the default browser (`open` /
     `xdg-open` / `cmd /c start`) and returns to the menu. When the Web build
     (`daedalus-web/dist`) is present, the server serves that UI from `/`
     while the JSON API remains on its named routes; if no build is present,
     `/` returns service JSON with a Web hint instead of pretending the UI is
     available;
   - `serve` runs the foreground server, `status` reports pid/url/health,
     `stop` gracefully stops the recorded server and reports if it is
     already gone.
3. **Tray is a capability, not a promise.** The tray manager checks for a
   desktop session (`DISPLAY` / `WAYLAND_DISPLAY` / macOS / Windows). Its
   menu exposes *Open CLI*, *Open Web*, *Status*, and *Quit*; Quit invokes
   the injected host quit handler before hiding the tray backend, while
   stopping the background server remains the daemon lifecycle's job
   (`daedalus stop` / `stopDaemon()`). When no desktop
   session or native tray backend is available the CLI and Web honestly
   report "no tray in this environment" and name `daedalus status` /
   `daedalus stop`. The tray lifecycle/menu logic is isolated in
   `cli/src/tray.ts` behind an injectable backend so a missing optional
   dependency never breaks `daedalus run` or the bare launcher. This build
   bundles no native tray backend, so a real desktop tray icon is not
   claimed as verified in this VM.
4. **Headless verification is first-class.** Launch, reuse, menu routing,
   and start/stop state transitions are covered by Vitest tests against a
   fake server. Tray lifecycle logic (menu contents, Quit ordering, and the
   desktop-session check) is unit-tested without requiring a display; a real
   desktop tray is verified manually by the owner on their machine and is
   never claimed as machine-verified in this VM.

## Consequences

- The terminal remains the universal entry point and the launcher cannot
  create duplicate servers.
- `daedalus run` stays a foreground, JSON-capable command for scripts.
- Desktop behavior is honest about its verification limits instead of
  pretending a hidden display exists.
