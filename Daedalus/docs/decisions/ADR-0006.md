# ADR-0006: Phase 8.5 Product Session, Modes, Providers, and Attachments

## Context

Phases 0–8 proved one agent core behind two thin interfaces, but the product
surface had no persistent interaction model: CLI and Web could start a task,
yet could not share agent modes, slash-command behavior, provider/model
selection, attachment state, or settings. The implementations must stay
interface-neutral: no agent, tool-selection, approval, or provider logic may
move into the CLI, server, or Web code.

The user's five adult product modes are `ask`, `manual`, `auto`, `plan`, and
`orchestrator`. They are behavioral modes of the same agent, not five products.

## Decision

1. **Core owns the mode policy.** `@daedalus/core` exposes `AgentMode`,
   `ModeController`, `AGENT_MODE_ORDER`, and mode helpers. The controller is a
   small stateful object whose `mode` is read at each turn boundary; therefore
   a Shift+Tab change can never alter the tool set mid-tool-call.
2. **Modes restrict both offered tools and executed tools.** `AgentLoop`
   filters schemas handed to the provider using `ModeController.visibleTools`,
   then re-checks execution against the current mode before dispatching a tool.
   A fabricated or stale tool call gets a typed denied result rather than
   reaching the harness.
   - `ask` and `plan`: read-only tools only;
   - `manual`: all tools, every mutating/executing call approval-gated;
   - `auto`: all tools, ordinary approval policy plus session auto-approve;
   - `orchestrator`: all tools, same approval semantics as the session policy,
     with child-task bookkeeping.
   Switching into or out of `orchestrator` is recorded with a `MODE_CHANGED`
   event and forces a re-plan on the next turn boundary.
3. **Mode changes are events.** Contracts add `MODE_CHANGED`,
   `SLASH_COMMAND_EXECUTED`, `PROVIDER_CHANGED`, `ATTACHMENT_ADDED`,
   `CHILD_TASK_STARTED`, and `CHILD_TASK_FINISHED`. The append-only log remains
   the parity source for terminal, Web, and replayed views.
4. **Slash commands live once in core.** `SlashCommandRegistry` parses,
   autocompletes, documents, and dispatches the PLAN.md command set through a
   `SlashCommandContext` implemented by each host. The registry never logs or
   returns raw API keys and reports unknown or malformed commands as text, not
   exceptions escaping to the UI.
5. **Providers live behind a core registry.** `ProviderRegistry` / persistent
   `ProviderRegistryStore` hold display name, OpenAI-compatible base URL,
   server-side API key, model list/default model, vision capability, and
   enabled flag. Public views are masked (`ProviderConfigPublic`); API keys are
   never serialized into those views, events, settings endpoints, or logs.
   Presets include the user's 9Router endpoint and a custom endpoint. A "test"
   performs a real `GET /models` call through the provider HTTP layer.
6. **Attachments are workspace-confined metadata plus data.** Core defines
   `Attachment` metadata. The server owns upload limits, path sanitization,
   ZIP/folder handling, and stored bytes under the workspace
   `.daedalus/attachments/<taskId>` directory or a scoped upload root selected
   by the server. The Web/CLI only stage metadata returned by those checks.
   Core's context builder lists attachments for every task and includes image
   bytes as `image_url` data URLs only when TaskRunner has resolved that the
   selected provider/model supports vision; it resolves image paths inside
   the task workspace before reading them.
7. **Orchestrator children are recorded task specs.** `ChildTask` carries
   `id`, `parent_task_id`, `goal`, optional `mode`, status, and optional
   `budget` `{ max_iterations, max_errors }`. Children run sequentially by
   default and are linked back into the parent event log; the child budget is
   passed into each child AgentLoop and the parent run's iteration/error
   budget is enforced as a total across children. A no-progress stop or total
   budget stop cancels later children and the parent reports the aggregate
   outcome after combined validation when all children complete.
8. **Greenfield creation is a first-class tool.** Core's default registry adds
   `create_dir` (mutating) and `write_file` ensures parent directories exist,
   so a scaffold cannot fail simply because its folders were not pre-created.

## Consequences

- The CLI, server, and Web stay thin: they present controls and translate API
  inputs into core calls.
- Mode, provider selection, and slash commands have one implementation and one
  test surface.
- Provider secrets exist only server-side in process memory and, when the
  server chooses persistence, in a mode-`0600` JSON store under the Daedalus
  home. Browser state never receives the plaintext key.
- Image bytes are sent to a model only when that model's `supports_vision`
  flag resolves true for the selected provider/model; otherwise the
  interface and prompt say in words that the image bytes were not sent.
