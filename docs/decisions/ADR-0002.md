# ADR-0002: Technology Stack and Tooling

## Context
The framework needs a portable TypeScript runtime, thin terminal and web interfaces, realtime updates, and unified verification.

## Decision
Use Node.js 22+, TypeScript ESM, npm workspaces, Commander, a Node HTTP/WebSocket backend, the existing React/Vite frontend, and Vitest. Use an OpenAI-compatible provider configured by `LLM_BASE_URL`, `LLM_API_KEY`, and `LLM_MODEL`; default base URL is `https://llm.ayid.cc.cd/v1`.

## Consequences
One language and test runner reduce integration friction. Provider-specific response formats stay behind a core adapter. The existing web scaffold remains in place.
